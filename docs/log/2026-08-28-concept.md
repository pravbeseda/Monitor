# 2026-08-28 — Design notes: how the project started

*Outcome documents: [concept.md](../concept.md) and [poc.md](../poc.md). These notes keep
the reasoning and the rejected options that did not fit into them.*

## The original ask

A "control panel for life": a briefing of indicators, fast focus on whatever needs
attention, depth and history on demand, notifications. It should hook the way a strategy
game does, but the emphasis is on comfortable reading, not on game mechanics. Nothing
off-the-shelf does the last part.

## Visual concepts considered

1. **City** (the SimCity metaphor): districts are life areas, buildings are metrics, state
   is read visually — smoke over a server, a park growing wild. The hook is the aesthetics
   of order rather than points. Cost: an expensive visual layer.
2. **Mission control**: a dark board, empty when everything is fine, sorted by anomaly
   (z-score against the metric's own norm), top five oddities. Judged the most practical
   core.
3. **Advisors** (from Civilization): per-domain agents writing short summaries in plain
   language. Cheap to build, strong effect, works as a morning ritual.
4. **Organism**: metrics as body systems with a single "pulse" number for a watch or phone
   widget.

Resolution: the concepts combine rather than compete. Mission control first, advisors
second, city as an alternative mode later.

## The requirement that decided the architecture

Several visual concepts must be pluggable and switchable. Everything else followed from
that, and is recorded in [ADR 0001](../decisions/0001-semantic-core-and-skins.md). The
warning worth repeating: skin-specific fields must never enter the State API contract —
semantics only, and each skin does its own translation into visuals.

## Honest remarks from the discussion

- Roughly 70% of the lower layer already exists off the shelf (Grafana, VictoriaMetrics,
  Home Assistant, `node_exporter`). This project's added value is the normalization and
  prioritization layer on top — not storage, not charting.
- Manual input for finance via a bot is a feature-ritual, not a workaround.
- A silence detector is mandatory: without it a dashboard lies quietly.
- Notification rule: only red is instant, yellow goes into a digest. Otherwise the bot is
  muted within a month.

## Naming

Round one, visual and strategic: Helm, Bridge, Sentinel, Beacon, Vantage, Skyline, Atlas,
Domain, Citadel, Realm, Vitals, Pulse, Homeostat. Favourites: Helm, Vantage, Vitals, Domain.

Round two, control and assistant words without visual metaphors: Tracker, Monitor, Ledger,
Telemetry, Gauge, Keeper, Steward, Curator, Adjutant, Butler, Herald, Tripwire, Ping.
Favourites: Steward, Adjutant, Tripwire, Ledger.

Observation: *role* words (Steward, Butler) imply a character and set the tone of
notifications; *mechanism* words (Tracker, Gauge) stay neutral.

**Chosen working title: Monitor.** Names from the shortlists are reserved for components —
Herald for the notifier, Tripwire for the threshold engine.
